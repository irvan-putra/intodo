# Review canvas (static, GitHub Pages)

A standalone static build of the section-by-section review canvas for
irvan-putra/intodo, pinned to the commit recorded in `../src/sections.ts`
(generated by `../tools/gen_sections.py`; re-run the generator after any
repo change so the cards match the pinned commit).

Full-screen, FreeForm/Miro-style: the canvas fills the whole window - no
page framing, no square viewport, and no navigation controls or minimap.
Drag the background or a fixed card to pan; pinch to zoom. The zoomed-out
levels follow the C4 model (c4model.com): furthest out is the system context
(people - including the owner in the developer role - the intodo system, and
external systems: Instinct Files, GitHub, GitHub Actions draft workflows, and
the DeltaChat network); one level in is the container view - the repo's
runnable units (itdapk, itdxdc, itdweb, and the feed encryption CLI), with
test suites attached to the containers they verify and build/CI plus repo
docs kept as one honestly-labeled supporting group. Relationships on that
level are labeled and code-evidenced at the pinned commit: solid lines are
runtime flows or evidenced manual steps seen in the source; dashed lines are
design similarity or designed-but-never-deployed pieces (see the legend).
Both GitHub Actions workflows are REVIEW DRAFTS with manual triggers only -
no automatic CI runs on push, and the Pages deploy is a separate manual path.
Tap a container to open
its sections. At closer levels, tap a card's Focus to read it (on phones that
opens a full-screen readable overlay; on larger screens the camera focuses
the card). Honest limits: the feed publish step happens outside this repo (encrypt_feed.py only
emits ciphertext); the Android and webxdc merge implementations share an
algorithm but have no runtime link.

Unlike the hosted canvas in `../src/App.tsx`, this variant:

- has no platform dependency: `files-shim.tsx` replaces `@instinct/files`
  with a tiny localStorage-backed `useLocalState`, so the review UI runs
  as a plain static page;
- pans infinitely: camera x/y are unclamped (zoom still clamped);
- keeps review marks and camera position in the visitor's browser only
  (localStorage key prefix `intodo-review.`); cards cannot be rearranged.
  A notice appears only if saving fails. Nothing is sent anywhere; marks from
  the hosted canvas do not carry over (different origin and storage);
- shows public repo content only: section text and public file links.

## Build and deploy

    sh itdweb/review/build.sh            # writes itdweb/review/dist/
    # on the gh-pages branch:
    mkdir -p review && cp /path/to/dist/* review/
    git add review && git commit -m "itdweb: static review canvas" && git push

The page then lives at https://vanipy.com/intodo/review/ alongside the
existing demo at /intodo/.
